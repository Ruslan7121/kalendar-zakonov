# Инструкция для ИИ-агента: «Календарь законов»

Это рабочая инструкция для любого ИИ-агента (Claude, GPT, Gemini и других), который подключился к проекту. Прочитай её целиком, прежде чем что-то менять.

Сайт: <https://ruslan7121.github.io/kalendar-zakonov/>
Репозиторий: <https://github.com/Ruslan7121/kalendar-zakonov>

---

## 1. Что работает без тебя

Сбор данных и публикация **не зависят от ИИ**. По будням с **21:17 по Москве** запускается `.github/workflows/daily.yml`: его запускает цикл `news` (см. таблицу ниже), расписание 21:17 — запасное, повторы в 22:47 и 23:47 МСК идут, только если за вечер ещё не было успешного прогона. Его также можно запустить вручную: Actions → daily → Run workflow, день можно указать. Workflow выполняет по порядку:

1. `pipeline/run_daily.sh` собирает за день:
   - голосования с vote.duma.gov.ru;
   - календарь заседаний;
   - законопроекты и пояснительные записки с sozd;
   - время голосований;
   - документы СФ, Минфина, Минтруда, Минюста и ЦБ;
   - путь закона.

   Потом он проводит аудит и составляет список задач `out/TODO.md`.
2. `pipeline/validate_data.mjs` проверяет схему данных. Битые данные дальше не идут.
3. Запускаются проверка типов и все тесты (`pipeline/ci_tests.sh`).
4. `pipeline/commit.sh` делает коммит и push в `main`.
5. `pipeline/publish.sh` выкладывает сайт в ветку `gh-pages`.

Если не готовы только тексты (код 3 у `tests/run_all.sh`: SHORT, «Суть», метки, тексты органов), данные дня всё равно коммитятся и публикуются, коммит помечается «— тексты не готовы». Если упал любой другой тест, в `main` уходят только сырые данные (`pipeline/commit_raw.sh`, коммит «Сырые данные … без публикации»), сайт не обновляется, прогон помечается ошибкой. Так же устроен `organs`.

Кроме `daily`, есть ещё workflow. Все, кроме `news`, можно запустить вручную (Actions → имя → Run workflow):

| Workflow | Что делает |
|---|---|
| `laws` | Ищет прямые ссылки на тексты законов «Вступают в силу» (kremlin.ru, затем publication.pravo.gov.ru) и проверяет уже стоящие. Сверяет полноту с подборками Госдумы «Какие законы вступают в силу». Коммит и публикация. |
| `organs` | **Каждые 3 часа круглосуточно** (в 1, 4, 7, 10, 13, 16, 19 и 22 часа МСК его запускает цикл `news`; расписание 1:13, 4:13, …, 22:13 МСК — запасное) и вручную: документы и новости органов за 7 дней (вручную можно указать «from» — дату начала — и «only» — `pres` или `gov`, тогда собирается только указ Президента или акты Правительства за длинное окно) — заседания СФ, приказы Минфина и Минтруда, указания ЦБ, коллегии Минюста, **указы и распоряжения Президента, постановления и распоряжения Правительства** (API publication.pravo.gov.ru). Без ИИ. Коммит и публикация. |
| `news` | **Цепочка без перерыва, день и ночь** (расписание GitHub задерживает и пропускает запуски, поэтому на него нельзя полагаться): один запуск живет почти 6 часов (`pipeline/news_loop.sh`), днем с 8:00 до 22:00 по Москве собирает каждые 20 минут, ночью раз в час, перед лимитом сам запускает следующий; cron раз в час — запасной. Этот же цикл запускает `organs` каждые 3 часа (1, 4, 7, 10, 13, 16, 19, 22 ч МСК) и по будням с 21:17 МСК `daily`, если сегодня он еще не шел; если вечерний `daily` упал или отменен, с 22:30 до 23:45 МСК повторяет его (не чаще раза в 30 минут, не больше двух повторов). Что собирает: оперативные новости для вкладки «Новости» (`pipeline/news_live.py`: Госдума, Правительство, СФ, ЦБ, Минфин, Минтруд, Минюст — заголовок, время, ссылка). Выкладывает только `data/live.json` (`publish.sh --live`), main не меняет. |
| `notes` | Вручную: догружает пояснительные записки к законопроектам за дни с голосованиями, начиная с указанного дня (поле «from», по умолчанию 01.10.2026), в `extracts/bills/*.json`. Нужен, чтобы по старым законопроектам написать «Суть», метки и пары «Что сейчас / Что предлагалось изменить». Сайт не меняет. |
| `probe` | Скачивает страницы по адресам и печатает их устройство. Нужен для разбора новых источников, ничего не меняет. |
| `tests`, `deploy` | Проверки и публикация после слияния PR в `main`. |

`news` идёт в своей очереди (`news-live`) и не мешает остальным. `daily`, `laws` и `organs` стоят в одной очереди (`daily-run`) и не идут одновременно. В очереди может ждать только один запуск: новый запуск отменяет ожидающий.

После этого на сайте уже есть всё, что собрано автоматически: голосования (итог, фракции, время), повестка, путь закона, документы органов и новости. **Если ИИ в этот день не подключился, сайт всё равно обновится.** Не появятся только тексты, которые пишет ИИ (раздел 2).

Ручной прогон — те же шаги одной цепочкой:

```bash
bash pipeline/run_daily.sh 11.11.2026
```

```bash
node pipeline/validate_data.mjs
```

```bash
bash pipeline/commit.sh "Обновление календаря за 11.11"
```

```bash
bash pipeline/publish.sh "Обновление календаря за 11.11"
```

## 2. Что делаешь ты

Автоматика не пишет тексты по смыслу. Твоя работа:

| Что | Куда | Откуда брать |
|---|---|---|
| «Суть» (1–2 предложения, раздел 6, правило 13) и «Кого коснётся» | `BP[номер]` (через `out/days/ГГГГ-ММ-ДД.json` → `python3 pipeline/bp_merge.py`) | пояснительная записка в `extracts/bills/<номер>.json` (поле `note`; если она скан — текст законопроекта к 1-му чтению, `note_kind`), для нерассмотренных вопросов повестки то же; `fin` (ФЭО) и `committee` (заключение) — дополнительно; сообщение на duma.gov.ru |
| Для «О внесении изменений»: пары «Что сейчас» / «Что предлагалось изменить» | `BP[номер].bs` | сравнительная таблица (`table` в `extracts/bills/<номер>.json`), иначе записка и текст законопроекта (`note_kind`) |
| Метки «Для кого», «Тема», «Что меняется» | `ZTAG[номер]` в `src/canvas.tsx` (три массива) | официальное содержание; списки меток — `ZW`, `ZT`, `ZC` в коде |
| Название и суть для автоматически добавленных законов | `LAWS` | kremlin.ru, publication.pravo.gov.ru |
| «Суть» документа органа (кроме Госдумы): **3–4 абзаца** — что документ меняет или устанавливает, главные нормы и сроки, на кого распространяется, с какого момента действует; и «Кого коснётся» | файл `{"<id события>": {"sut": ["абзац", …], "who": "…"}}` → `python3 pipeline/orgx_merge.py ФАЙЛ` (пишет `out/organs/enrich.json` и блок `ORGX`) | официальный текст в `extracts/organs/<ключ>.json` (собирает `pipeline/organ_texts.py` в workflow `organs` и `organ_texts`; поле `kind`: `text`/`ocr`/`html`, `fail` — текст не получен). Сведения о регистрации и опубликовании — не «Суть». К каждому документу — **короткое название** `ti` (5–10 слов, помещается в 1–2 строки, без «Приказ № …»; поле в том же файле: `"ti": "…"`), его показывает карта органов; без `ti` сайт сокращает «Суть» сам, но хуже. Список документов без «Сути» — раздел «Суть документов органов» в `out/TODO.md` |

Что именно нужно написать сегодня, перечислено в **`out/TODO.md`**: его составляет `pipeline/todo.py`.

Порядок работы:

1. Обнови рабочую копию: `git pull --ff-only` на ветке `main`.
2. Проверь, собран ли день: `git log --oneline -5 --grep "Ежедневный прогон"`.
   - Если коммит «Ежедневный прогон ДД.ММ.ГГГГ» уже есть, сбор сделал GitHub Actions. Не запускай `run_daily.sh` повторно, а только составь список задач: `python3 pipeline/todo.py`. Выжимки пояснительных записок `extracts/bills/*.json` с 15.11.2026 лежат в git.
   - Если коммита нет, запусти `bash pipeline/run_daily.sh ДД.ММ.ГГГГ` (нужен доступ к RU-прокси) или workflow `daily` с этим днём.
3. Открой `out/TODO.md` и напиши тексты по выжимкам из `extracts/bills/`. Список идёт от свежих дней к старым: сначала законопроекты без «Сути», потом пары «Что сейчас / Что предлагалось изменить», потом метки законов `tg`, постановления — по желанию.
   - Тексты законопроектов: файл `out/days/ГГГГ-ММ-ДД.json` вида `{"bp": {"<номер>": {"sut": [...], "who": "...", "bs": [["было", "стало"]]}}}`, затем `python3 pipeline/bp_merge.py src/canvas.tsx out/days/ГГГГ-ММ-ДД.json`. Поля сливаются по одному: можно прислать одни `bs`, «Суть» не сотрётся.
   - Метки законопроектов: в тот же файл дня добавь `"ztag": {"<номер>": [[«Для кого»], [«Тема»], [«Что меняется»]]}` и запусти `python3 pipeline/ztag_merge.py src/canvas.tsx out/days/ГГГГ-ММ-ДД.json`: метки проверяются по `ZW`/`ZT`/`ZC`, номер убирается из `ZAUTO`.
   - Не заводи свои блоки данных (как бывшие `BP1112`, `TRACK1112`): только `BP`, `ZTAG`, `LAWS`. Иначе скрипты и TODO их не увидят.
   - Законопроекты без меток ежедневный сбор размечает сам временными метками (`pipeline/auto_ztag.py`, по словам названия) и записывает номера в `ZAUTO`. Уточни их метки в `ZTAG` по пояснительной записке и убери номер из `ZAUTO` — они в разделе TODO «Метки законопроектов».
   - У нового закона в `LAWS` должно быть поле `added` (UTC, `2026-11-21T14:30:00Z`: когда закон появился в ленте). По нему бот присылает подписчикам «Новый закон в «Вступают в силу»»; без поля уведомления не будет (автодобавленные законы получают его от `track.py`).
   - У нового закона в `LAWS` должны быть `title`, `sut`, `who`, `tg` (`[[«Для кого»], [«Тема»], [«Что меняется»]]` из `ZW`/`ZT`/`ZC`) и `src` только с официальными ссылками. По `tg` закон попадает в RSS-ленты меток.
4. Проверь себя:
   - нет выдуманных чисел, дат и фамилий;
   - у каждого факта есть официальный источник.
5. Проверь данные и тесты:

   ```bash
   node pipeline/validate_data.mjs
   ```

   ```bash
   npm test
   ```

6. Закоммить и опубликуй:

   ```bash
   bash pipeline/commit.sh "Тексты за ДД.ММ"
   ```

   ```bash
   bash pipeline/publish.sh "Тексты за ДД.ММ"
   ```

7. Коротко отчитайся владельцу: что обновлено, что осталось без данных и почему (по `out/logs/*.log`), SHA коммитов в `main` и `gh-pages`.

Если не успел всё, коммить то, что готово. Остальное останется в `out/TODO.md` на следующий запуск: сайт от этого не ломается.

## 3. Правила, которые нельзя нарушать

- **Источники только официальные:** vote.duma.gov.ru, sozd.duma.gov.ru, duma.gov.ru, council.gov.ru, government.ru, kremlin.ru, publication.pravo.gov.ru, cbr.ru, сайты министерств. Если в источнике чего-то нет, поле остаётся пустым, ничего не додумывается.
- Тексты на русском. Буква «ё» заменяется на «е» автоматически (`clean_yo.py`).
- Данные живут в `src/canvas.tsx` (блоки `DATA`, `CAL`, `BP`, `ZTAG`, `TRACK`, …). `data/*.json` и `src/canvas.code-only.tsx` производные: их пересобирают `split_data.mjs` и `strip_code_only.py`, руками их не правят.
- Скрипты пишут `src/canvas.tsx` только через `common.write_canvas`: там атомарная запись, проверка блоков и резервная копия в `out/cache/canvas.prev.tsx`. Если правишь руками, после правки запусти `node pipeline/split_data.mjs` и `node pipeline/validate_data.mjs`.
- Коммиты обычные: без `--force`, `--amend` и `--no-verify`. Ветку `gh-pages` пишет только `publish.sh`.
- Сайт публикуется только на GitHub Pages.
- Не меняй интерфейс, если владелец об этом не просил. Твоя задача — данные и тексты.

## 4. Если что-то сломалось

| Симптом | Что делать |
|---|---|
| `votes_day: список голосований не загружен` | Источник недоступен, сайт открывается только с российских адресов. `fetch.sh` сам ищет RU-прокси, повтори через час. Данные не испорчены. |
| `validate_data: N ошибок` | Смотри `out/logs/validate_data.txt`, исправь запись в `src/canvas.tsx`. Пока ошибки есть, `publish.sh` не публикует сайт. |
| `canvas: … не разбирается как JSON` | Запись отменена, файл цел. Последняя хорошая версия лежит в `out/cache/canvas.prev.tsx`. |
| `run_daily: уже идёт другой прогон` | Подожди, пока закончится первый. Два прогона одновременно не запускаются. |
| Тест упал | Найди причину. Тесты не отключай и не пропускай. |
| Workflow `daily` упал | Открой лог в Actions → daily. Если это недоступный источник, следующий запуск повторит. Если упал тест (коммит «Сырые данные … без публикации»), найди причину в данных или коде, исправь, прогони `npm test` и опубликуй день сам (раздел 6). |

## 5. Где что лежит

- `pipeline/` — сбор, проверка, коммит, публикация. Подробно в [docs/PIPELINE.md](docs/PIPELINE.md), доступ к сайтам в [docs/ACCESS.md](docs/ACCESS.md).
- `BOT_PROMPT.md` — подробные правила текстов и интерфейса.

## 6. Постоянные правила бота «Госдума Сводки»

Раздел закрепляет правила, по которым работает бот «Госдума Сводки». Подробные правила текстов и интерфейса — в [BOT_PROMPT.md](BOT_PROMPT.md), здесь они не повторяются.

### Роль

- Бот собирает данные из официальных источников, готовит сводки и **единственный вносит правки в сайт**: код, данные, карточки, перенос макетов.
- Макеты и дизайн делает Дизайнер. Его макет переносится в календарь только после сигнала «макет готов».
- Публикация — только на GitHub Pages и в этот репозиторий. Страницу Cursor не править.
- README держать актуальным: после изменения конвейера, расписания или интерфейса обновить соответствующий раздел.

### Правила формирования информации

1. **Источники только официальные:** duma.gov.ru, sozd.duma.gov.ru, vote.duma.gov.ru, government.ru, kremlin.ru, council.gov.ru, cbr.ru, publication.pravo.gov.ru; из агентств — ТАСС, РИА Новости, Интерфакс. Ничего не выдумывать. Если данных нет, в отчёте назвать номер документа и причину.
2. **Значок чтения** — строго по СОЗД или vote.duma.gov.ru. Значка «ратификация» нет.
3. **«Путь закона»** строится по истории СОЗД: пройденные шаги — зелёная сплошная линия, следующий шаг — пустой, с пунктиром.
4. **«Суть» и «Кого коснётся»** есть во всех карточках с официальными данными, включая ЦБ. Формулировка всегда «Кого коснётся».
5. **Все голосования дня** вносятся в календарь. Время голосования показывается под «Итогами голосования».
6. **Совет Федерации:**
   - каждый вопрос заседания — отдельная карточка;
   - статус берётся из официального итога;
   - новости — только из ленты council.gov.ru/events/news за этот день.
7. **Календарь и новости не дублируются:** акт — в календаре, новость о нём — в новостях.
8. Блоков «Работа в комитетах» и «Работа в регионах» нет.
9. **Фильтры «Для кого», «Тема», «Что меняется»:**
   - на каждой карточке голосования есть чипы всех трёх групп;
   - метки ставятся только по официальному содержанию;
   - недостающая метка создаётся (сначала в `ZW`/`ZT`/`ZC`, затем в `ZTAG`);
   - при каждом обновлении фильтры пересматриваются.
10. **Перед сдачей** проверяется весь комплект за день или неделю: полнота, отсутствие дублей, чипы.
11. **«Поделиться»** ведёт только на github.io со ссылкой `?d=&v=`. Карточка открывается с шапки. На телефоне — одна кнопка «Поделиться карточкой» внизу карточки. Подробно — BOT_PROMPT.md, «Правило 11».
12. В фильтре органов есть кнопка «Убрать все».
13. **Тексты дня:**
    - SHORT — 2–5 слов;
    - FULL — полное официальное название;
    - «Суть» — 1–2 предложения, «Кого коснётся» — по пояснительной записке;
    - образец качества — тексты за 17.11.2026.
14. Карточка по ссылке с `v=` показывает именно своё голосование (чтение, итог, время).
15. **Полная повестка дня** — повестка, объединённая с фактическими голосованиями. Нерассмотренные пункты помечаются «не рассм.».
16. **Документы госорганов:**
    - с 19.11.2026 документ без «Сути» и «Кого коснётся» на сайте скрыт (`ORG_HIDE_FROM`); тексты пишутся в течение часа после сбора;
    - более ранние документы показываются всегда, блок «Суть» появляется, когда текст написан;
    - вкладка «Работа госорганов» открывается картой органов (плитки за день, неделю, месяц → лента органа → окно документа); в превью — вид, номер и короткое название `ti`, без «Кого коснётся» и без новостей; заседания и голосования Госдумы — в режиме «По дням»;
    - закрытые документы — одной строкой;
    - долг по текстам ведётся в `out/TODO.md`.

Дополнительно:

- у законопроектов с фильтром «Налоги» или явно посвящённых налогам «Кого коснётся» обязательно;
- скриншоты правок — в 4 вариантах: компьютер и телефон, светлая и тёмная тема;
- сайт проверяется и в Яндекс Браузере на телефоне.

### Бюджетные законопроекты

Образец — карточки 615-9 и 616–621-9 (ноябрь 2026, см. docs/CHANGELOG.md за 20.11.2026).
- «Суть» — короткие абзацы с цифрами из пояснительной записки и ФЭО, без пояснений терминов и без итогов голосования: «Суть» общая для карточек всех дней, итог каждого дня показан в самой карточке.
- В окне законопроекта — блок «Главное» с плитками: для закона о бюджете это доходы, расходы и дефицит на следующий год с изменением к текущему году и к прежнему плану; красное — хуже для бюджета, зелёное — лучше. Для ФОМС, Соцфонда и связанных законопроектов — ключевые цифры из записки (доходы, расходы, остатки, пенсии, МРОТ, ставки и т. п.).
- Блоки «Бюджет по годам» (отчёт, оценка, плановые годы, без горизонтальной прокрутки на телефоне) и «Было → Стало» (действующий закон против законопроекта). Данные `BUDGET[номер]` пишут `pipeline/budget.py` и `pipeline/bill_facts.py` только по официальным документам.
- В переключателе голосований — только чтения (1-е, 2-е, 3-е); голосования по таблицам поправок открываются только по ссылке `?v=`.

### Расписание

Время московское. Workflow запускает цикл `news` (`pipeline/news_loop.sh`), расписание в `.github/workflows` — запасное.

| Когда | Кто | Что происходит |
|---|---|---|
| Каждые 3 часа: 1:13, 4:13, 7:13, 10:13, 13:13, 16:13, 19:13, 22:13 | `organs` | Документы и новости органов за 7 дней, официальные тексты новых документов. |

Если не готовы только тексты, данные всё равно коммитятся и публикуются, тексты бот дописывает своим проходом.
