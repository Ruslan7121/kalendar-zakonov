# Инструкция для ИИ-агента: «Календарь законов»

Это рабочая инструкция для любого ИИ-агента (Claude, GPT, Gemini и других), который подключился к проекту. Прочитай её целиком, прежде чем что-то менять.

Сайт: <https://ruslan7121.github.io/kalendar-zakonov/>
Репозиторий: <https://github.com/Ruslan7121/kalendar-zakonov>

---

## 1. Что работает без тебя

Сбор данных и публикация **не зависят от ИИ**. По будням в **21:17 по Москве** GitHub Actions запускает `.github/workflows/daily.yml`. Его также можно запустить вручную: Actions → daily → Run workflow, день можно указать. Workflow выполняет по порядку:

1. `pipeline/run_daily.sh` собирает за день:
   - голосования с vote.duma.gov.ru;
   - календарь заседаний;
   - законопроекты и пояснительные записки с sozd;
   - время голосований;
   - документы СФ, Минфина, Минтруда, Минюста и ЦБ;
   - путь закона.

   Потом он проводит аудит и составляет список задач `out/TODO.md`.
2. `pipeline/validate_data.mjs` проверяет схему данных. Битые данные дальше не идут.
3. Запускаются проверка типов и все тесты.
4. `pipeline/commit.sh` делает коммит и push в `main`.
5. `pipeline/publish.sh` выкладывает сайт в ветку `gh-pages`.

После этого на сайте уже есть всё, что собрано автоматически: голосования (итог, фракции, время), повестка, путь закона, документы органов и новости. **Если ИИ в этот день не подключился, сайт всё равно обновится.** Не появятся только тексты, которые пишет ИИ (раздел 2).

Ручной прогон — те же шаги одной цепочкой:

```bash
bash pipeline/run_daily.sh 11.11.2026
```

```bash
node pipeline/validate_data.mjs
```

```bash
bash pipeline/commit.sh "Обновление календаря за 11.11"
```

```bash
bash pipeline/publish.sh "Обновление календаря за 11.11"
```

## 2. Что делаешь ты

Автоматика не пишет тексты по смыслу. Твоя работа:

| Что | Куда | Откуда брать |
|---|---|---|
| «Суть» (1–3 абзаца) и «Кого коснётся» | `BP[номер]` (через `out/days/ГГГГ-ММ-ДД.json` → `python3 pipeline/bp_merge.py`) | пояснительная записка в `extracts/bills/<номер>.json` (поле `note`), сообщение на duma.gov.ru |
| Для «О внесении изменений»: пары «Что сейчас» / «Что предлагалось изменить» | `BP[номер].bs` | та же записка |
| Метки «Для кого», «Тема», «Что меняется» | `ZTAG[номер]` в `src/canvas.tsx` (три массива) | официальное содержание; списки меток — `ZW`, `ZT`, `ZC` в коде |
| Название и суть для автоматически добавленных законов | `LAWS` | kremlin.ru, publication.pravo.gov.ru |

Что именно нужно написать сегодня, перечислено в **`out/TODO.md`**: его составляет `pipeline/todo.py`.

Порядок работы:

1. Обнови рабочую копию: `git pull --ff-only` на ветке `main`.
2. Если прогон за день ещё не сделан, запусти `bash pipeline/run_daily.sh ДД.ММ.ГГГГ`.
3. Открой `out/TODO.md`, напиши тексты по выжимкам из `extracts/bills/`.
4. Проверь себя:
   - нет выдуманных чисел, дат и фамилий;
   - у каждого факта есть официальный источник.
5. Проверь данные и тесты:

   ```bash
   node pipeline/validate_data.mjs
   ```

   ```bash
   npm test
   ```

6. Закоммить и опубликуй:

   ```bash
   bash pipeline/commit.sh "Тексты за ДД.ММ"
   ```

   ```bash
   bash pipeline/publish.sh "Тексты за ДД.ММ"
   ```

7. Коротко отчитайся владельцу: что обновлено, что осталось без данных и почему (по `out/logs/*.log`), SHA коммитов в `main` и `gh-pages`.

Если не успел всё, коммить то, что готово. Остальное останется в `out/TODO.md` на следующий запуск: сайт от этого не ломается.

## 3. Правила, которые нельзя нарушать

- **Источники только официальные:** vote.duma.gov.ru, sozd.duma.gov.ru, duma.gov.ru, council.gov.ru, government.ru, kremlin.ru, publication.pravo.gov.ru, cbr.ru, сайты министерств. Если в источнике чего-то нет, поле остаётся пустым, ничего не додумывается.
- Тексты на русском. Буква «ё» заменяется на «е» автоматически (`clean_yo.py`).
- Данные живут в `src/canvas.tsx` (блоки `DATA`, `CAL`, `BP`, `ZTAG`, `TRACK`, …). `data/*.json` и `src/canvas.code-only.tsx` производные: их пересобирают `split_data.mjs` и `strip_code_only.py`, руками их не правят.
- Скрипты пишут `src/canvas.tsx` только через `common.write_canvas`: там атомарная запись, проверка блоков и резервная копия в `out/cache/canvas.prev.tsx`. Если правишь руками, после правки запусти `node pipeline/split_data.mjs` и `node pipeline/validate_data.mjs`.
- Коммиты обычные: без `--force`, `--amend` и `--no-verify`. Ветку `gh-pages` пишет только `publish.sh`.
- Сайт публикуется только на GitHub Pages.
- Не меняй интерфейс, если владелец об этом не просил. Твоя задача — данные и тексты.

## 4. Если что-то сломалось

| Симптом | Что делать |
|---|---|
| `votes_day: список голосований не загружен` | Источник недоступен, сайт открывается только с российских адресов. `fetch.sh` сам ищет RU-прокси, повтори через час. Данные не испорчены. |
| `validate_data: N ошибок` | Смотри `out/logs/validate_data.txt`, исправь запись в `src/canvas.tsx`. Пока ошибки есть, `publish.sh` не публикует сайт. |
| `canvas: … не разбирается как JSON` | Запись отменена, файл цел. Последняя хорошая версия лежит в `out/cache/canvas.prev.tsx`. |
| `run_daily: уже идёт другой прогон` | Подожди, пока закончится первый. Два прогона одновременно не запускаются. |
| Тест упал | Найди причину. Тесты не отключай и не пропускай. |
| Workflow `daily` упал | Открой лог в Actions → daily. Обычно это недоступный источник: следующий запуск повторит. |

## 5. Где что лежит

- `pipeline/` — сбор, проверка, коммит, публикация. Подробно в [docs/PIPELINE.md](docs/PIPELINE.md), доступ к сайтам в [docs/ACCESS.md](docs/ACCESS.md).
- `BOT_PROMPT.md` — подробные правила текстов и интерфейса.
- `docs/CHANGELOG.md` — журнал изменений, `docs/TODO.md` — накопленные задачи.
- `web/` — сборка сайта, `web/extras.mjs` — страницы законопроектов, RSS и `.ics`.
- `tests/` — все тесты, запуск: `npm test`.
