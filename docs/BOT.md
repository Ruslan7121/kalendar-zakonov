# Бот @kalendar_zakonov_bot

Сервер бота — Cloudflare Worker `bot/worker.mjs` с базой D1 (`bot/schema.sql`). Сайт и мини-приложение работают и без него: сервер нужен для ответов бота и статистики.

| Что | Как |
|---|---|
| `/start` | приветствие и кнопка «📅 Открыть календарь» (мини-приложение) |
| `/stats` | только владельцу (`OWNER_ID`), в меню команд видна только ему: новые за сегодня, активные за сегодня / 7 дней / 30 дней, всего |
| Учет | пользователь бота (любое сообщение) или мини-приложения (при открытии сайт отправляет `Telegram.WebApp.initData` на `/hit`, подпись проверяется по токену). Хранится только `sha256(соль:id)`, первый и последний визит; имен и логинов нет |
| Сутки | по Москве; «активные за 7 / 30 дней» — последний визит не раньше 7 / 30 суток назад |

## Развернуть (один раз, потом — при изменении `bot/`)

1. Cloudflare: зарегистрироваться на dash.cloudflare.com, открыть **Workers & Pages** (при первом входе Cloudflare предложит выбрать поддомен `*.workers.dev`).
2. Cloudflare → **My Profile → API Tokens → Create Token** → шаблон **Edit Cloudflare Workers**, добавить право **Account → D1 → Edit** → создать, скопировать токен. **Account ID** — на главной странице аккаунта справа.
3. GitHub → репозиторий → **Settings → Secrets and variables → Actions → New repository secret**:
   `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`, `BOT_TOKEN` (новый токен из @BotFather), `OWNER_ID` (ваш числовой id — пришлет @userinfobot).
4. GitHub → **Actions → bot → Run workflow**. В итогах запуска — адрес сервера `https://kalendar-zakonov-bot.<поддомен>.workers.dev`.
5. Адрес вписать в `STATS_URL` в `src/canvas.tsx` (рядом с `TG_APP`) и опубликовать сайт — с этого момента мини-приложение отправляет отметки об открытии.

Токены — только в секретах GitHub и Cloudflare, не в коде и не в чатах. Тест без сети: `node tests/js/test_bot.mjs`.

## Уведомления в Telegram (21.11.2026)

Человек выбирает метки «Для кого» и «Тема» в окне «Мои интересы» (приложение; метки двух групп работают вместе), включает нужные уведомления и при желании задаёт тихие часы. Настройки: **результат рассмотрения законопроекта** (в каком чтении рассматривали, итог «принят / отклонён», голоса, о чём законопроект: карточка приходит в бот с кнопкой «Открыть карточку»), **новый закон в «Вступают в силу»** (сообщение, когда закон с вашими метками добавлен в ленту: дата вступления в силу и суть; работает для законов с полем `added`, которое ставит `track.py` при автодобавлении; законы, добавленные вручную, должны получать `added` от того, кто их добавляет), **закон вступает в силу завтра**, **тихие часы** (по умолчанию 22:00–08:00; время начала и конца задаётся в приложении и считается по часовому поясу устройства, начало = конец: тихих часов нет). Мини-приложение отправляет настройки на `POST /sub` вместе с подписанной `initData` (`{w, t, prefs: {vote, new, soon, quiet, qs, qe, tz}}`); сервер проверяет подпись и хранит `chat_id`, метки и настройки в таблице `subs` (только у тех, кто сам включил уведомления; выключил в приложении — строка удаляется).

Раз в 15 минут (cron в `bot/wrangler.toml`) воркер читает `feed/events.json` сайта (его строит `web/extras.mjs`: результаты рассмотрения за 7 дней по каждому чтению, новые законы (поле `added` не старше 7 дней), законы за сутки до вступления в силу; у каждого имена меток `tw` и `tt`) и пишет подписчикам по пересечению меток. Событие уходит один раз (таблица `sent`), не раньше момента подписки, не больше 5 сообщений за запуск и не в тихие часы (сообщения придут после их окончания). Если пользователь заблокировал бота, подписка удаляется.

Чтобы заработало: развернуть воркер (см. выше, до `STATS_URL` включительно: без адреса приложение показывает «Служба уведомлений ещё не подключена») и после обновления `bot/` снова запустить workflow `bot` (схема D1 создаёт таблицы `subs` и `sent`, cron подхватывается из `wrangler.toml`). Тест без сети: `node tests/js/test_bot.mjs`.
