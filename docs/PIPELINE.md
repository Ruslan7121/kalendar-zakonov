# Программа (pipeline/)

Переменные: GD_ROOT (по умолчанию /workspace; canvas — $GD_ROOT/out/canvas.tsx), GD_DUMA (каталог со списками прокси lists/), GD_FETCH (путь к fetch.sh), GD_DAYS (каталог days/*.json голосований; по умолчанию $GD_ROOT/duma/days).

| Скрипт | Что делает | Пишет |
|---|---|---|
| run_daily.sh [ДД.ММ.ГГГГ] | прогон за день с прогрессом: **votes_day (шаг 1)** → calendar → bills → vote_times → track → **audit.py --day** → todo + сводка. | — |
| votes_day.py ДД.ММ.ГГГГ [ДД.ММ.ГГГГ] [--dry-run] [--canvas файл] | **шаг 1.** Голосования дня с vote.duma.gov.ru: список `?from=&to=` (все страницы `page=`) + страница каждого голосования `/vote/<id>` (итог, поимённо → фракции, дата и время). Пишет days/ДД.ММ.ГГГГ.json, затем аддитивно DATA: новые id вставляются по порядку, существующие строки не меняются (расхождения цифр — в отчёт), Суть/TRACK/ZTAG/постановления не трогаются. VT — время со страницы голосования. День без голосований (официально «ничего не найдено») в DATA не добавляется. Код выхода: 0 — ок, 1 — есть пробелы (голосования не попали в DATA), 2 — список дня недоступен, DATA не изменён. | $GD_DAYS/ДД.ММ.ГГГГ.json, DATA, блок VT, out/cache/vote/<id>.html, logs/votes_day_<день>.json, logs/votes_day_fail.log |
| calendar_update.py, embed_calendar.py | календарь (CAL) | out/calendar.json, canvas |
| bills.py [дни] | все законопроекты: sozd + пояснительная записка (docx/pdf). **Ускорено:** 10 воркеров, задержка 0.12 с. | out/extracts/bills/*.json, logs/bills_fail.log |
| bills.py --one <номер> | ручная догрузка одного законопроекта | out/extracts/bills/<номер>.json |
| vote_times.py [дни] | время голосования для всех id из DATA. Источники по порядку: days/*.json (от votes_day.py) → страница голосования `/vote/<id>` → **запасной путь:** страница депутата (Абакаров, 99113478; не даёт времени, если депутат отсутствовал). Время берётся только при совпадении даты. | блок VT, logs/vote_time_fail.log |
| track.py [номера] [--refresh] | все этапы (in/kom/r1/r2/r3/sf/sign/pub/force) с sozd; отклонение = дата голосования; force с kremlin.ru при совпадении номера и даты. Без аргументов — все bills из DATA. TRACK_QUICK=1 — только локальный кэш duma/bills. | блок TRACK, LAWS (auto), logs/track_fail.log, logs/laws_auto.log |
| audit.py [--day ДД.ММ.ГГГГ] [--fix] | независимый аудит canvas vs sozd/vote: метка чтения, TRACK-даты (только полный прогон), день DATA vs дата голосования, card_vs_share (карточка и шаринг — одна SoT чтения). В daily — только `--day`. | out/logs/audit_*.json |
| budget.py [номер] [docx] | бюджетный блок из пояснительной записки | блок BUDGET |
| todo.py | список текстов для бота | out/TODO.md |
| bp_merge.py | перенос текстов бота (out/days/*.json) в BP/PROC | canvas |
| strip_code_only.py | src/canvas.code-only.tsx | out/canvas.code-only.tsx |
| summary.sh [день] | сводка по логам парсинга | — |
| fetch.sh, testdom.sh | загрузка через RU-прокси, проверка прокси | — |

Строка DATA (votes_day.py): `id|номер (или «Пост. N», «—»)|краткое название|чтение|1/0|за/против/возд./не голос.|ЕР;КПРФ;ЛДПР;НЛ;СРЗП;Вне` (размер фракции через «:», если отличается от 350/37/24/20/17/2). Для «к отклонению» — чтение законопроекта и 0 (законопроект отклонён), как в существующих строках.

Блоки в canvas.tsx, которые переписывает программа: `/* VT:start */…/* VT:end */`, `/* TRACK:start */…/* TRACK:end */`, `/* BUDGET:start */…/* BUDGET:end */`.

## Ограничения (06.11.2026)
- vote.duma.gov.ru не ответил через прокси — время голосований пока «нет данных». Добавлен запасной способ через прямой запрос. *(12.11.2026: через fetch.sh и RU-прокси vote.duma.gov.ru отвечает; проверка votes_day.py за 10.11 и 11.11 — 64/64 и 71/71 голосований, цифры и VT совпали с DATA, кроме флага «принят» у трёх «к отклонению», учтено.)*
- Дата вступления в силу: поиск kremlin.ru не находит свежие законы; текст по ссылке используется только при совпадении номера ФЗ и даты подписания. Пока ни одна дата не подтверждена.
- Бюджет: суммы по разделам есть только на 2027–2029 (законопроект). За 2025 (отчет) и 2026 (оценка) в записке — только основные характеристики (доходы, расходы, дефицит); суммы по разделам за прошлые бюджеты не загружены.
- bills.py: ускорен до 10 воркеров и задержки 0.12 с. Повторный запуск продолжает с места остановки (готовые json пропускаются).
