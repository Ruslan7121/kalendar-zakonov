# Экономия токенов при работе ИИ-агента

Измерено 22.11.2026 по журналам сессий (`npx ccusage daily`, 12–22.11): записано около 4 млн токенов ответа и около **2,76 млрд токенов чтения кэша**
(примерно 700 к 1). Стоимость определяет не объем написанного, а **размер диалога, который перечитывается на каждом шаге**.
Значит, экономят: короткий контекст, меньше лишних шагов, короткие результаты команд. Качество от этого не страдает.

## Правила
1. **Не печатать длинные строки.** `src/canvas.tsx` — несколько строк по сотням КБ. Только `pipeline/peek.py` (ниже) или `rg -o` с обрезкой `.{0,70}…`,
   `cut -c1-200`, `head`. Перед выводом списка — счетчики, а не перечисление (`peek.py debt`).
2. **Одна пачка независимых вызовов в одном шаге**, а не по одному.
3. **Шумную или долгую работу — субагенту** (массовое чтение выжимок, ожидание проверок): в диалог вернется короткий итог, а не весь вывод.
4. **Новая тема — новая сессия.** Долгий диалог дорожает с каждым шагом; итог прошлой сессии лежит в `docs/CHANGELOG.md` и `out/TODO.md`.
5. **Не копить задачи.** Выполненные задачи в списке удаляются: список целиком возвращается в диалог при каждом напоминании.
6. **Читать нужный кусок:** `Read` с `offset`/`limit`, `peek.py note/text` вместо всей записки или файла.
7. Ожидание CI — один цикл с `sleep` внутри команды, а не серия коротких проверок (`peek.py ci`).

## Инструменты
| Что | Зачем | Как |
|---|---|---|
| `pipeline/peek.py` | компактные запросы к канону и данным: карта кода, поиск, законопроект, записка, документ органа, долг, CI | `python3 pipeline/peek.py` (справка) |
| `ccusage` | измерение: токены и стоимость по дням и сессиям | `npm run usage` (из `package.json`) |
| `ast-grep` | структурный поиск по TSX без чтения файла: `ast-grep run -l tsx -p 'function F($$$){$$$}' --json=compact` | `pip install --user ast-grep-cli` |

Проверено и **не** установлено:
- `rtk` (Rust Token Killer, сжатие вывода команд): собирается из GitHub/crates.io, оба недоступны из среды; пакет `rtk` в npm — другой проект (релизный инструмент), его ставить нельзя.
- Серверы MCP (Serena, context-mode и др.): описания инструментов попадают в контекст на каждом шаге, то есть увеличивают главную статью расхода; выигрыш есть только на больших кодовых базах.
