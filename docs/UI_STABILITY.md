# Стабильность интерфейса: как это устроено

Три механизма, которые не дают интерфейсу «прыгать» (22.11.2026). Правьте их в одном месте, а не в каждом компоненте.

## 1. Экран и клавиатура — `src/ui/viewport.ts` (`useViewport`)
На iPhone окно Telegram и «видимая область» (`visualViewport`) меняются не одновременно, поэтому закреплённые элементы (нижняя панель вкладок, «Наверх», звёздочка, кнопка календаря) не двигаются вслед за клавиатурой. Вместо этого:
- пока набирается текст или область «съехала», на `<html>` стоит атрибут `data-kb`, а CSS скрывает эти элементы (`html[data-kb] … { visibility: hidden }`);
- после закрытия клавиатуры состояние перепроверяется через 0,15 / 0,45 / 0,9 / 1,6 с и элементы возвращаются на место;
- переменные CSS `--gd-vh` (высота видимой области) и `--gd-kb` (1 или 0) доступны любому стилю;
- слушаются `visualViewport`, прокрутка и размер окна, события Telegram (`viewportChanged`, `safeAreaChanged`), фокус полей ввода.

Новое закреплённое внизу экрана: добавьте его селектор в правило `html[data-kb] …` (раздел `css` в `src/ui/theme.tsx`).

## 2. Слои и «назад» — `src/ui/layers.ts` (`useEscape`)
Окна, ленты и панели регистрируются как слои: `useEscape(слой_открыт, () => закрыть())`. Escape (и кнопка «назад» Telegram, которая шлёт Escape) закрывает **только верхний** слой. Не вешайте свой `keydown` на Escape.

## 3. Тесты
- `tests/js/test_webkit.browser.mjs` (WebKit, как на iPhone): имитация клавиатуры (окно становится ниже, панель скрыта, поле видно, потом всё возвращается), Escape закрывает слои по одному, фокус не теряется на первой букве.
- `tests/js/test_cls.browser.mjs` (Chromium): сдвиг макета (CLS) при загрузке, переключении вкладок и открытии окна; порог 0,05, замер 22.11.2026 — 0,000. В тесте есть контрольный сдвиг, чтобы нули не были ложными.
- Настоящую клавиатуру Telegram на телефоне это не заменяет: после правок в этих местах проверяйте на iPhone.
